## Mathematical analysis (Section 9)
**A. Continuity:** the exponential full-cluster kernel exp(-d(q,h_i)/tau_local), summed over a FIXED finite member set, is continuous (indeed Lipschitz on any bounded region) in q wherever d(.,.) is -- unlike a top-k operator, whose selected neighbor SET can change discontinuously as q moves. This script's basis functions (RBF, linear anchor-difference) are likewise smooth in q, so the smoothness mismatch CRISP must address is between the exact full-cluster function and a FINITE-RANK approximation of it, not between smooth and discontinuous operators.
**B. Effective dimensionality:** the E2 error-vs-rank curve above is the direct empirical evidence for this -- a sharp drop-then-plateau indicates a low effective dimensionality for the evidence function on the sampled clusters; a slowly-decaying curve indicates otherwise. Continuity (A) alone does not imply this.
**C. Projection error vs. distribution error:** when total evidence mass m_j(q) is small, a given absolute error in s~ translates into a LARGER relative error in the normalized distribution F~ -- this is exactly why E2/E3 report total variation on the NORMALIZED distribution (and the E2 mass_relative_error field) rather than only raw evidence error.
**D. Storage complexity:** a rank-r model stores r coefficients per (cluster, token) pair plus O(r) shared anchor/basis metadata per cluster -- parameters scale with (number of clusters) x (average distinct tokens per cluster) x r, NOT with cluster population; this is CRISP's structural storage advantage over retaining members directly (B4), whose cost scales with the number of RETAINED VECTORS x the full hidden-state dimension (768), independent of how many distinct tokens the cluster has.
**E. Limitations:** ridge regression minimizes squared error unconstrained by nonnegativity or the simplex constraint; this script corrects negative evidence by clipping (frac_evidence_mass_clipped in the JSON), which is a post-hoc correction, not a property the fitting objective itself guarantees. Reconstructed evidence also has no awareness of DIME's own top-k outer selection -- CRISP only changes what happens AFTER a cluster is already retrieved, never whether it is retrieved.

## Verdict: Partially supported
CRISP's reconstructed distributions are meaningfully closer to the exact within-cluster evidence than DIME-V1's static histogram at r=8, within a storage budget well below raw kNN -- but this delivery only covers 20 sampled clusters and bounded query samples (Phase 1-3), so full-scale storage/fidelity at all 3,811 clusters remains unverified.

## Limitations (Phase 1-3 scope, Phase 4 deferred)
- 20 of 3811 clusters evaluated, not all -- storage figures in E5 are EXTRAPOLATED from this sample's average tokens/cluster, not a full-scale measurement.
- Per-cluster fit/tune/test query counts bounded to 150/50/100.
- Rank grid capped at 32 (64 deferred).
- No base-LM interpolation or end-to-end perplexity anywhere in this script, per the spec's own Section 4 scope -- all comparisons are distributional (JS/TV/top-1/top-k/entropy) against the exact within-cluster evidence function and DIME-V1's static histogram.
- tau_local is a single global constant (not tuned per cluster/rank), consistent with this project's established 'single global constant' precedent for shared hyperparameters.
- E3/E4/CRISP-B are PER-CLUSTER reconstruction-fidelity comparisons, not a full multi-cluster top-20 mixture evaluation -- only the 20 sampled clusters have a fitted CRISP model, so a real query's other ~19 retrieved clusters have no model to combine with yet. A full end-to-end mixture test needs every retrieved cluster fitted, which is exactly the Phase 4 full-scale extension this delivery defers.
